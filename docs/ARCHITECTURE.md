# Архитектура

## Данные и поток работы

`SVG-исходник → выбранные контуры → компонент → экземпляры на холсте → SVG-экспорт`.

Исходники включены в `public/assets/originals`. Каталог описывает 20 иллюстраций
и доступные логические объекты. Для трёх исходников есть подготовленные копии:
в них исходные пути помечены `data-component`, а повторяющиеся ID заменены
уникальными. Алгоритм подготовки воспроизводится Python-скриптом, но Python
не требуется для запуска приложения.

У `dog-jump` общий акцентный путь содержит независимые замкнутые контуры:
один из них — язык собаки. Он вынесен в отдельный путь без изменения команд.
Тест сравнивает объединённые команды с оригиналом.

## Извлечение

`src/svg.ts` разбирает подготовленный SVG через DOMParser. Он сохраняет пути
выбранного объекта, необходимые родительские группы и определения SVG.
Это важно: цвет, правила заливки и transform могут быть заданы у родителя.

Временный невидимый SVG помещается в DOM, браузер вычисляет getBBox с учётом
родительских преобразований. Компонент получает нормализованные координаты,
размеры, имя и ссылки на исходник и логическую группу. Временный SVG удаляется
в finally. Векторные пути не растрируются.

## Компонент и экземпляр

Компонент содержит SVG-фрагмент и исходные размеры. Экземпляр сцены содержит
ссылку на компонент, собственные x/y, масштаб и угол. Поэтому дублирование
не меняет исходник и не связывает преобразования копий.

Порядок элементов массива сцены совпадает с порядком SVG-групп: последний
объект рисуется поверх остальных. В списке слоёв этот порядок показан сверху вниз.
Масштабирование и поворот выполняются вокруг центра объекта; при смене масштаба
позиция корректируется, чтобы центр не сдвигался.

Pointer Events и обратная матрица getScreenCTM переводят координаты мыши
из экранных пикселей в систему координат холста 1200 × 800.

## Сохранение

localStorage хранит версионированный JSON: название, выбранный исходник,
ссылки на компоненты и экземпляры сцены. SVG-разметка в JSON не сохраняется.
При загрузке проверяются версия, ссылки, уникальность ID и числовые параметры;
фрагменты заново извлекаются из локальных подготовленных SVG.

Запись откладывается на 300 мс после изменения и выполняется также при скрытии
или закрытии страницы. Если восстановление или запись не удались, пользователь
видит сообщение. Данные не перезаписываются автоматически после ошибки;
можно явно сохранить новую сцену вместо прежней. Экспорт остаётся доступным.

## Экспорт

`src/export.ts` строит новый SVG из модели сцены, а не копирует DOM редактора.
Каждый экземпляр становится отдельной группой с тем же transform, источником
и объектом компонента. ID вложенных элементов и внутренние ссылки получают
уникальные префиксы, поэтому копии не конфликтуют.

В файле нет рамок выделения, элементов интерфейса или растровых изображений.
Фон прозрачный. Экспорт проверен как XML и открыт отдельно в браузере.

## Почему без backend

Для одного пользователя и локальной библиотеки сервер не нужен. Браузер
уже предоставляет SVG DOM, измерение геометрии, Pointer Events, Blob и
localStorage. Это оставляет время на обязательный сценарий тестового задания.
